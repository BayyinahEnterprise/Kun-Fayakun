## Title

furqan-lint vs. bandit: A Finding-Count Comparison Across 25 Python Codebases

## Description

### What this is

This dataset accompanies the paper "furqan-lint vs. bandit: A Finding-Count Comparison Across 25 Python Codebases." It contains the complete empirical record of a head-to-head benchmark between two static analysis tools -- furqan-lint v2.1.0 and bandit 1.9.4 -- run across 25 of the most widely-used open-source Python packages, totaling 2,327,868 lines of code and 5,252 files. Every finding from both tools is shipped as raw JSON, making the dataset fully replayable and independently verifiable without installing either tool.

### What furqan-lint does

furqan-lint is a multi-language static analysis tool that checks for *structural honesty* -- whether a program's surface behavior (what its interface claims) matches its substrate behavior (what its implementation actually does). It detects patterns that fall between the cracks of existing tool categories: not style violations (ruff, flake8), not type errors (mypy, pyright), and not known CVEs (bandit, semgrep), but structural gaps where code's claims and code's behavior diverge. Examples include exception handlers that catch everything and handle nothing, parameters named "password" containing hardcoded strings, and **kwargs accepted and forwarded without validation.

The tool implements 50 unique rules across six languages -- Python (42 rules, 39 active by default), C, C++, Java, C#, and Ada/SPARK -- using AST analysis for Python and tree-sitter parsing for the other five. A single conceptual framework covers all six languages: a bare `except:` in Python, a `catch(...)` without rethrow in C++, and a `when others => null;` in Ada are the same structural dishonesty pattern expressed in different syntax.

### What the benchmark found

With symmetric test-path exclusion applied to both tools, furqan-lint produces more findings than bandit in all 25 packages (pooled ratio 6.3x, median per-package ratio 5.3x). As run (with furqan-lint's SI-006 exempting test files while bandit's B101 does not), furqan-lint leads in 22 of 25 packages (pooled ratio 0.83x, median 5.0x), with the three reversals (numpy, pandas, scipy) driven entirely by bandit's B101 firing on test assertions.

Two furqan-lint rules account for 58.6% of its output: SI-001 (Any type annotation, 47.1%) and SI-006 (assert in non-test code, 11.5%). SI-001 overlaps with ruff's ANN401. The paper is transparent about this concentration and frames the results as a finding-count comparison, not a claim of superior defect detection. The false positive rate is not measured.

### Why this matters

Existing static analysis tools for Python cover style (ruff), types (mypy), and known security patterns (bandit). furqan-lint's rules address a region these tools leave unexamined -- structural gaps between interface and implementation. Whether this constitutes a genuinely complementary analysis class is an open empirical question (the paper says so explicitly), but the 54,892 findings from both tools across 25 production codebases provide the raw material for anyone to investigate that question further.

### What's in the dataset

- **The paper** -- PDF and markdown source, independently verified by a fresh non-Anthropic audit seat (PASS WITH REVISIONS)
- **benchmark_v2.1.0.csv** -- 25-package results with per-severity columns
- **raw_json/** -- furqan-lint's 24,933 findings as per-package JSON (rule, file, line, column, message, severity, fix category)
- **bandit_json/** -- bandit's 29,959 findings as per-package JSON
- **benchmark.py** -- the harness, with `--from-json` offline replay mode and `--scan` for fresh runs, all paths parameterized
- **versions.json** -- exact Python, bandit, and per-package versions used
- **rule_manifest.json** -- machine-readable inventory of all 50 rules (rule ID, language, source file, default activation status)
- **test_output_v2.1.0.txt** -- 208 tests passing
- **REPRODUCIBILITY.md** -- environment setup, replay instructions, standalone/monorepo equivalence documentation
- **furqan-lint v2.1.0 source** -- the complete tool (standalone pip-installable package + monorepo source + tree-sitter adapters for C/C++/Java/C#/Ada)
